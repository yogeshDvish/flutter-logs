## 2. PRODUCT OVERVIEW
SealedTrace is a secure logging platform built by Arovyx Studio:
  - SealedTrace SDK (Flutter/Dart package `sealed_trace`) — the client. It seals
    every log batch with hybrid encryption ON DEVICE. This spec does NOT cover
    the SDK, but the client-server contract (section 3) is FIXED and shared with
    the SDK team — implement it exactly, byte-for-byte on field names.
  - SealedTrace Server (this spec, part A): .NET 8 + ASP.NET Core Web API + EF
    Core + SQL Server.
  - SealedTrace Console (this spec, part B): React 18 + TypeScript web dashboard
    where users create projects, connect the SDK, and view/search logs.
Security model (NON-NEGOTIABLE): logs arrive encrypted; ONLY the server can
decrypt them (RSA private key per project). Device-side attackers see only
ciphertext. Plaintext logs exist only in server memory during ingest and in
SQL Server (TDE at-rest encryption is a deployment choice — note it).

## 3. FIXED CLIENT-SERVER CONTRACT (shared with SDK — do not alter)
### 3.1 SealedEnvelope (upload request item; also the on-disk client format)
{
  "v": 1,
  "batchId": "<uuid-v4>",
  "projectId": "<uuid-v4>",
  "createdAt": "2026-01-01T10:00:00.000Z",
  "eventCount": 25,
  "alg": "RSA-OAEP-2048-SHA256+AES-256-GCM",
  "wrappedKey": "<base64>",
  "iv": "<base64, 12 bytes>",
  "tag": "<base64, 16 bytes>",
  "ciphertext": "<base64>"
}
Decryption = RSA-OAEP-2048 (SHA-256) unwrap wrappedKey -> AES-256-GCM key;
AES-GCM decrypt(iv, ciphertext, tag) -> UTF-8 JSON array of LogEvent objects.
(.NET: RSAEncryptionPadding.OaepSHA256 + AesGcm class, 12-byte nonce.)
### 3.2 LogEvent (the decrypted payload item)
{
  "id": "<uuid-v4>", "seq": 1234,
  "ts": "2026-01-01T10:00:00.000Z",
  "level": "verbose|debug|info|warning|error|fatal",
  "tag": "auth", "message": "<masked text>",
  "error": "<masked text or null>", "stackTrace": "<masked text or null>",
  "metadata": { }, "sessionId": "<uuid or null>", "userId": "<string or null>",
  "ctx": { "appVersion": "1.2.3", "buildNumber": "45",
           "platform": "android|ios|web|windows|macos|linux",
           "os": "...", "locale": "en_IN", "env": "prod",
           "network": "wifi|mobile|none|unknown" }
}
### 3.3 Ingest API
POST /api/v1/ingest/logs
  Headers: X-Api-Key: <apiKey>, Content-Type: application/json
  Body: { "envelopes": [ SealedEnvelope, ... ] }  // max 50 envelopes / 2 MB
  202: { "accepted": ["batchId"], "duplicate": ["batchId"],
         "rejected": [{"batchId","reason"}] }
  Errors: 401 invalid key, 403 revoked key, 413 too large, 429 rate-limited.
### 3.4 Golden test vectors
tests/TestData/envelope_vectors.json (SAME file as SDK team's): fixed test-only
RSA keypair + known plaintext -> expected wrappedKey/iv/tag/ciphertext. Ingest
integration tests MUST decrypt these successfully. This proves cross-compat.

## 4. PART A — SealedTrace Server (.NET 8, ASP.NET Core Web API, EF Core, SQL Server)
### 4.1 Solution structure (pragmatic clean architecture)
SealedTrace.sln
  src/SealedTrace.Api           — controllers, middleware, DI, Swagger
  src/SealedTrace.Core          — entities, DTOs, interfaces, domain services
  src/SealedTrace.Infrastructure — EF Core DbContext, SQL Server, repositories,
                                   crypto services
  src/SealedTrace.Jobs          — hosted background services (retention)
  tests/SealedTrace.Tests       — xUnit unit + integration tests
                                 (WebApplicationFactory + Testcontainers MSSQL)
Base namespace: Arovyx.SealedTrace.*
Optional docker-compose.yml: api + sqlserver (latest), healthchecks.

### 4.2 Features
A. Auth: register/login/refresh/logout — JWT access token 15min + refresh token
   30d with rotation (RefreshTokens table), BCrypt.Net-Next password hashing,
   /me endpoint. JWT via Microsoft.AspNetCore.Authentication.JwtBearer.
B. Projects (multi-tenant per user): CRUD, name, slug, retention policy fields
   (maxAgeDays, maxEvents — nullable = defaults).
C. Key management per project:
   - API keys: 32-byte RandomNumberGenerator key (returned to user EXACTLY
     once on creation), store only SHA-256 hash + display prefix (first 8
     chars). Revoke endpoint (soft revoke: RevokedAtUtc).
   - Project RSA keypair: RSA.Create(2048) per project. PublicKeyPem stored
     clear; PrivateKeyEncrypted = AES-256-GCM of the private PEM with master
     key from configuration ("SealedTrace:MasterKey"; document Azure KeyVault
     upgrade path; MasterKeyVersion column supports rotation). Private key
     cached decrypted in IMemoryCache per project.
D. Ingest endpoint (section 3.3): validate API key -> project, enforce size +
   rate limits, dedup by batchId (IngestBatches table, unique PK), decrypt each
   envelope (RSA.Decrypt OaepSHA256 -> AesGcm.Decrypt), parse + validate events
   (level enum; reject ts > now+5min), save Logs rows + IngestBatches row in
   ONE transaction, respond 202. p95 < 300ms for a 50-envelope request. Use
   EF Core bulk insert (AddRange) + SaveChanges batching.
E. Query API (JWT auth + project ownership check):
   GET /projects/{id}/logs?level=&tag=&from=&to=&userId=&sessionId=&search=
       &cursor=&limit=(<=200) — keyset pagination on (ClientTs DESC, Id DESC),
       cursor = base64("ts|id"); search via SQL Server Full-Text on Message
       (FromSqlRaw CONTAINS) with LIKE fallback (decide in implementation
       file).
   GET /projects/{id}/stats?from=&to= — level distribution, events/day, top
       tags, top user ids.
F. Retention job (BackgroundService, nightly, e.g. 03:00): per-project policy,
   batched DELETE (10k rows per loop) to avoid long locks.
G. Hardening: rate limiting per API key (ASP.NET 8 built-in RateLimiter,
   fixed window 600 req/min per key — or AspNetCoreRateLimit; pick one),
   ingest body limit 2MB (Kestrel MaxRequestBodySize + JSON options), CORS
   restricted to console origin, Serilog structured logging (file + console,
   REDACT api keys/private keys), /health + /health/ready (DB check via
   Microsoft.Extensions.Diagnostics.HealthChecks), Swashbuckle Swagger with
   Bearer + X-Api-Key security schemes.
H. Observability: counters (ingest accepted/duplicate/rejected, decrypt
   failures) via System.Diagnostics.Metrics + prometheus-net to /metrics
   (optional — note it).

### 4.3 SQL Server schema (EF Core migrations; same DDL as all SealedTrace variants)
Users(Id uniqueidentifier PK, Email unique, PasswordHash, Name, CreatedAtUtc)
Projects(Id PK, OwnerId FK, Name, Slug unique, CreatedAtUtc, RetentionMaxAgeDays
         null, RetentionMaxEvents null)
ApiKeys(Id PK, ProjectId FK, KeyHash, KeyPrefix, CreatedAtUtc, RevokedAtUtc null)
ProjectKeys(Id PK, ProjectId FK, Algorithm, PublicKeyPem, PrivateKeyEncrypted
            varbinary, MasterKeyVersion int, CreatedAtUtc)
IngestBatches(BatchId uniqueidentifier PK, ProjectId FK, ReceivedAtUtc,
              EventCount int, EnvelopeSize int)
Logs(Id uniqueidentifier PK, ProjectId FK, BatchId FK, ClientTs datetime2(3),
     ReceivedAtUtc, Level tinyint, Tag nvarchar(128), Message nvarchar(max),
     Error nvarchar(max) null, StackTrace nvarchar(max) null, MetadataJson
     nvarchar(max) null, SessionId uniqueidentifier null, UserId nvarchar(128)
     null, Seq bigint, AppVersion nvarchar(32) null, Platform nvarchar(16) null)
RefreshTokens(Id PK, UserId FK, TokenHash, ExpiresAtUtc, RevokedAtUtc null,
              ReplacedByTokenHash null)
Indexes: Logs(ProjectId, ClientTs DESC, Id DESC); Logs(ProjectId, Level,
ClientTs DESC); Logs(ProjectId, Tag); FULLTEXT catalog on Logs(Message) via
raw migration (EF Core does not manage full-text indexes).

### 5.2 Screens
